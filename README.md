# WhatEvent Lite — ระบบกลาง Event & Survey (สำหรับผู้เริ่มต้น)

เว็บตัวอย่างสำหรับฝึก Next.js + TypeScript โค้ดสั้น คอมเมนต์ภาษาไทยทุกไฟล์ ไม่ต้องมี backend (เก็บข้อมูลใน LocalStorage)

## รันโปรเจกต์
```bash
npm install
npm run dev     # เปิด http://localhost:3000
```

## บัญชีทดลอง
| Role  | ชื่อผู้ใช้ | รหัสผ่าน  | ทำอะไรได้ |
|-------|-----------|-----------|-----------|
| admin | admin     | admin1234 | เห็นเฉพาะ **กิจกรรมทั้งหมด** (สร้าง/แก้ไข/ลบ, รายงาน, ส่งออกภาพรวม) และ **มอบหมายผู้ดูแล** (รวมแท็บจัดการผู้ใช้) |
| user  | user1     | user1234  | login แล้วเข้า **แดชบอร์ดของกิจกรรม** ทันที จัดการได้เฉพาะกิจกรรมที่ admin มอบหมาย |

`user2` ไม่มีกิจกรรมที่ได้รับมอบหมาย ลอง login เป็น admin แล้วมอบหมายที่เมนู “มอบหมายผู้ดูแล”

## เมนูและหน้าต่าง ๆ
- เมนูซ้ายแสดงถาวร (ไม่พับ) มีโลโก้เว็บด้านบน (เปลี่ยนรูปได้ที่ `public/logo.png`) · user เห็นกิจกรรมที่ได้รับมอบหมายเป็นการ์ด (ดูแลหลายงานจะเป็นรายการให้กดสลับ ไม่มี dropdown)
- ธีมเว็บ 3 สี: กรมท่า `#16244f` · น้ำเงิน `#4a74ff` · ขาว `#ffffff` (ตั้งไว้ที่ต้นไฟล์ `app/globals.css`) สีของแต่ละงานใช้เฉพาะส่วนแบรนด์ของงาน
- ฟอนต์ทั้งเว็บ: Noto Sans Thai (ตั้งที่ตัวแปร `--font` ใน `app/globals.css`)
- ไอคอนใช้ไลบรารีจริง Lucide (แพ็กเกจ `react-icons`) ไม่ใช้อีโมจิ
- ดีไซน์แบบแบน ไม่มีเงา (drop shadow) ใช้เส้นขอบแทนทั้งเว็บ
- Sidebar สีกรมท่า จัดกลุ่มเมนูตามงาน (ภาพรวม / จัดการกิจกรรม / หน้างาน / ผู้ดูแลระบบ) ตามแบบ Sidebar ของ shadcn/ui
- user (ลำดับเมนู): แดชบอร์ด → ข้อมูลและสถานที่ → แบรนด์ → ผู้ลงทะเบียน → แบบสอบถาม → QR/ลิงก์ → Kiosk หน้างาน
- admin: กิจกรรมทั้งหมด (`/events`) และ มอบหมายผู้ดูแล (`/assignments`) เท่านั้น — เปิดหน้าของ user จะถูกพากลับไปหน้ากิจกรรมทั้งหมด
- ด้านล่างของเมนู: Admin แสดงป้าย "Admin" ส่วน User แสดงชื่อที่ตั้งไว้ พร้อมปุ่มออกจากระบบ
- มือถือ: เมนูย้ายไปอยู่แถบล่างจอ (ปุ่ม “เพิ่มเติม” มีเมนูที่เหลือ)
- สลับภาษา TH/EN และโหมดสว่าง/มืดได้ทุกหน้า

## ฟีเจอร์หลัก
- **งานเปิด / งานปิด** (หน้า ข้อมูลและสถานที่): งานเปิดไม่ต้องลงทะเบียน · งานปิดต้องลงทะเบียน และตั้งเวลาเปิด/ปิดรับ หรือหยุดรับชั่วคราวได้
- **แผนที่ Google Maps จากสถานที่ที่กรอก**: กรอกชื่อสถานที่/ที่อยู่ในการ์ดเดียวกัน แผนที่ Google Maps แสดงตำแหน่งตามข้อความ พร้อมปุ่มเปิดนำทาง (ไม่ต้องใช้ API key) · ถ้าใส่ API key (ไม่บังคับ) ช่องชื่อสถานที่จะมีรายการแนะนำจาก Google Places และเติมที่อยู่ให้อัตโนมัติ
- **แดชบอร์ด** 2 แท็บ: ภาพรวม (กราฟ) / รายงาน (ข้อสังเกตอัตโนมัติ, พิมพ์/PDF, Excel, CSV) — เปิดแท็บรายงานตรง ๆ ได้ที่ `/dashboard#report`
- **แบรนด์**: สีหลัก + สีรอง แสดงเป็นปุ่มสี กดแล้วมีกล่องเด้งขึ้นมาให้ปรับ RGB (แถบเลื่อน/ช่องตัวเลข R G B), รหัส HEX หรือจานสี · ฟอนต์ไทย 6 แบบ, สโลแกน, โลโก้และรูปพื้นหลัง+ความเข้มเงา พร้อมตัวอย่างบนมือถือ · สีรองใช้ไล่เฉดคู่กับสีหลักในหัวกิจกรรมและพื้นหลัง Kiosk (ปิดสีรองได้ ปิดแล้วใช้สีหลักสีเดียว ไม่ไล่เฉด) · ไม่มีตัวเลือกสไตล์ปุ่ม/ความโค้งมุม
- **แบบสอบถามแยกตามรูปแบบงาน**: งานเปิดสแกน QR แล้วตอบได้ทันที · งานปิดต้องยืนยันการลงทะเบียน (รหัสบัตร/อีเมล/เบอร์โทร) ก่อน และตอบได้คนละ 1 ครั้ง (ลิงก์ `/survey/รหัสงาน?t=รหัสบัตร` ยืนยันให้อัตโนมัติ)
- **ตัวแก้แบบสอบถาม**: เลื่อนขึ้น/ลง ทำซ้ำ แก้ตัวเลือกทีละช่อง และตัวอย่างหน้าผู้ตอบ
- **Kiosk หน้างาน**: หน้าจอจริงที่ `/k/รหัสกิจกรรม` (แนวตั้ง 1080×1920 เสมอ จอแนวนอนจะแสดงเป็นคอลัมน์แนวตั้งตรงกลาง มือถือเต็มจอ) ข้อมูลงาน (วันเวลา สถานที่ การเดินทาง) แสดงด้านบนเสมอ
  - งานเปิด: ไม่มีปุ่มลงชื่อ/ลงทะเบียน มี QR แบบสอบถามในการ์ดข้อมูลงาน
  - งานปิด: แสดงที่นั่งว่าง และปุ่ม 3 ปุ่ม — **เช็คอิน** (เปิดกล้องสแกน QR บัตรที่ได้จากการลงทะเบียน), **ลงทะเบียนหน้างาน** (แสดง QR ไปหน้าลงทะเบียนอย่างเดียว เฉพาะช่วงที่เปิดรับ), **แบบสอบถาม** (แสดง QR อย่างเดียว ผู้ตอบยืนยันการลงทะเบียนบนมือถือ)
  - สแกนด้วย BarcodeDetector ของเบราว์เซอร์ถ้ารองรับ ไม่รองรับก็ใช้ไลบรารี `jsqr` (ใช้ได้ทุกเบราว์เซอร์) · **กล้องใช้ได้เมื่อเปิดผ่าน HTTPS หรือ localhost เท่านั้น**

## แผนที่โฟลเดอร์ (อ่านตามลำดับนี้)
```
lib/types.ts         ข้อมูลของเรามีหน้าตาอย่างไร (User, EventItem, ...)
lib/brand.ts         ค่าเริ่มต้นแบรนด์/Kiosk, ฟอนต์, เติมค่าให้ข้อมูลเก่า
lib/lookup.ts        ค้นหาผู้ลงทะเบียนจากรหัสบัตร/อีเมล/เบอร์โทร
lib/db.ts            เก็บ/อ่าน LocalStorage + hook useStore + ข้อมูลตัวอย่าง
lib/auth.tsx         ระบบ login / logout
lib/eventContext.tsx กิจกรรมที่เลือกอยู่ (ใช้ร่วมกันทุกหน้า)
lib/i18n.tsx         สลับภาษา: เขียน t('ไทย', 'English')
lib/analytics.ts     ฟังก์ชันคำนวณตัวเลข/ข้อมูลกราฟ
lib/export.ts        ส่งออก CSV / Excel
app/page.tsx         หน้า Login
app/(main)/          หน้าหลัง login: (user) dashboard, details, branding, registrants, questions, share, kiosk · (admin) events, assignments, reports/[id]
app/register/[id]    หน้าลงทะเบียนของผู้เข้าร่วม (เปิดจาก QR)
app/k/[id]           หน้าจอ Kiosk หน้างาน
app/survey/[id]      หน้าแบบสอบถามของผู้เข้าร่วม (เปิดจาก QR)
components/          ชิ้นส่วนที่ใช้ซ้ำ (Sidebar, Charts, EventAnalytics, ...)
app/globals.css      สไตล์ทั้งหมด
```

## ข้อจำกัด
- ข้อมูลอยู่ในเบราว์เซอร์เครื่องที่ใช้ ลิงก์/QR ลงทะเบียนจึงเปิดผ่านเครื่องอื่นไม่เห็นข้อมูล (ต้องมี backend หรือ MockAPI)
- ตู้ Kiosk ต้องเปิดบนเครื่องเดียวกับที่มีข้อมูล (ใช้หลายเครื่องต้องมี backend)
- การตรวจสิทธิ์ทำที่หน้าเว็บเท่านั้น เหมาะกับการเรียนรู้ ไม่ใช่งานจริง

## Google Maps API key (ไม่บังคับ)
ใช้เติมที่อยู่อัตโนมัติจาก Google Maps เท่านั้น (Google ไม่เปิดข้อมูลที่อยู่ให้ดึงได้ถ้าไม่มีคีย์) แผนที่ที่แสดงไม่ต้องใช้คีย์
1. สร้าง API key ที่ Google Cloud Console แล้วเปิดใช้ **Maps JavaScript API** และ **Places API (New)**
2. วางคีย์ในไฟล์ `.env.local` ต่อท้าย `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY=` (แนะนำจำกัดคีย์ด้วย HTTP referrers เพราะคีย์ที่ขึ้นต้น NEXT_PUBLIC_ มองเห็นได้ในเบราว์เซอร์)
3. รัน `npm run dev` ใหม่
